# Patches

The verified source is the zlib-ng `develop` branch at commit `5f1f4899` (the `zlib-ng/` submodule) plus the patch
series in this directory.

## Layout and application rule

* One directory per fix, `NNNN-slug/`, numbered consecutively from `0001`. Each holds `upstream.patch`, a
  `git format-patch` series (one or more commits, as they are or will be proposed upstream, including their `test/`
  hunks), and `pr-summary.md` (title, Problem, Fix, Related Upstream References, Review Feedback Addressed, Testing).
  A directory whose series adds GoogleTest cases also holds `gtest.txt`, which lists them for
  `../tests/patch-gtest.sh`.
* **The verified source** is a copy of the submodule (without `.git`) with every `upstream.patch` applied in full,
  library and test hunks, by `git apply` (no fuzz, no three-way merge, offline), in directory name order; `git apply`
  applies the commits of one series in order. The result is the tree that `git am` of every series in that order
  gives. `../tests/apply-patches.sh` implements the rule (it sets `GIT_CEILING_DIRECTORIES` so that `git apply` never
  resolves paths against an enclosing work tree), and the project gate applies the series the same way.
* The Lean translation and the proofs are about the library part (everything outside `test/`);
  `../tests/build-zlib-ng.sh` builds that part (`apply-patches.sh --library-only`). Leaving out one patch for a
  reproduction leaves out its library hunks only.
* This README is the index: its table lists exactly the directories, in order (the gate checks it, and that each
  directory has both files and that the series apply in order).
* Number `0022` is reserved for the fix of the open `deflateReset` defect (`deflate-reset-block-open`, the last row of
  the findings page); it has no directory yet.

No series has been merged upstream. Each is replaced by the upstream fix
once one exists, and deleted once the pin moves past it. In this table, "local form" marks a series that is still the
single commit of the proved fix, with a summary of that form; its upstream-style message and GoogleTest cases are
pending.

History of patch 0004: its first version copied all four window copies of `inflate_fast` with `memcpy`, assuming
that the window and the output are distinct objects. `inflateBack` calls `inflate_fast_safe` with its output inside
the caller's window, so there a match that reaches into the previous pass of the window (`dist + min(op, len) >
wsize`) made `memcpy` copy between overlapping ranges, undefined (ISO C17 §7.24.2.1p2; AddressSanitizer
`memcpy-param-overlap`). This was a defect of our patch, not of upstream, and is not a finding. The `window == beg`
test above fixes it; `tests/regression/infback-window-overlap` runs `inflateBack` on such streams (windowBits 8, 9
and 15, overlapping copies and `dist == wsize`) without the patch and with it, both clean, and keeps the first
version (`first-0004.patch` there) as a guard that must still show the overlap.

History of patch 0002: its first version computed the target position before upstream's steps and returned -1
there. It refused every overflow, but it also changed what well-defined calls do: a `SEEK_CUR` refused because its
target lay before the start kept the pending skip, which upstream clears (on a reader and on a writer: `gztell` and the
next read or write then differ), and after `gzungetc` at position 0 a `SEEK_SET` to a negative offset was refused
where upstream seeks. This was a defect of our patch, not of upstream, and is not a finding. The current version
refuses only where upstream's arithmetic overflows. `tests/regression/gzseek-refusal-state` checks that such calls
give the same results and state with and without the patch, and keeps the first version (`first-0002.patch` there) as
a guard that must still differ.

History of patch 0013: its first version bounded `gz_read`, `gzgets` and the buffer fast path of `gzgetc` at
`GZ_OFF_MAX` but left the output buffer as `gz_fetch` filled it. The `gzgetc()` macro of `zlib.h` takes buffered bytes
and adds them to `x.pos` in the caller: after `gzseek(file, INT64_MAX - 2, SEEK_SET)` on Linux `/dev/zero`, `gzread` of
4 bytes returned 2 with 262142 bytes still buffered and the macro overflowed `x.pos`; stopping 11 bytes below the
maximum (a `gzread` of 1 byte after a seek to `INT64_MAX - 12`) and calling the macro 12 times overflows as well, so
an error raised only when a reader reaches `GZ_OFF_MAX` would not be enough. It also compared `(z_off64_t)n > GZ_OFF_MAX
- x.pos`: where `z_off64_t` is 32 bits (`zconf.h` gives `off_t` when there are no large-file functions, as with
`-D_LARGEFILE64_SOURCE=0` on a 32-bit system), an `n` above `INT_MAX` from `gzfread` converted to a negative number, the
bound was skipped and `x.pos` wrapped (unsigned arithmetic and an implementation-defined conversion, a wrong position).
These were defects of our patch (the first is the upstream overflow, now through the macro); `tests/regression/
gzgetc-macro-position` and `gzread-position-32bit` (a `-m32 -D_LARGEFILE64_SOURCE=0` build) keep the first version
(`first-0013.patch` there) as guards that must still show them.

History of patch 0014: its first version compared `len > (size_t)(GZ_OFF_MAX - x.pos)`. Where `size_t` is 32 bits and
`z_off64_t` 64 bits (a 32-bit build with `_FILE_OFFSET_BITS=64`), the conversion kept the low 32 bits of the room left,
so a legal write was refused: at `x.pos = 2^32 - 1` the room converted to 0 and a one-byte `gzwrite` returned 0 with
`Z_DATA_ERROR`. This was a defect of our patch, not of upstream, and is not a finding; the verified LP64 target was not
affected (`size_t` is 64 bits there). The current version compares in `uint64_t`. `tests/regression/gzwrite-position-32bit`
writes one byte at `2^32 - 1` (after `gzseek` there) on a `-m32 -D_FILE_OFFSET_BITS=64` build and keeps the first version
(`first-0014.patch` there) as a guard that must still refuse it.

Redundancy kept on purpose: patches 0013 and 0014 each define `GZ_OFF_MAX` under `#ifndef GZ_OFF_MAX` although patch
0002 defines it in `gzguts.h`. The copies are not dead: the reproduction of 0002 builds the source with every patch but
0002 (`tests/regression/run.sh`), and `gzread.c` and `gzwrite.c` then need their own definition to compile. The drain of
buffered output that a pending skip covers appears in `gzseek64` (upstream), `gz_skip` (upstream) and `gzdirect` (patch
0017). Doing it once, in a helper or in `gz_look`, would change two upstream functions that need no fix and add a
function, a larger diff against upstream than the five lines of 0017; it stays as it is.
