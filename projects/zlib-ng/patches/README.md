# Patches

The verified source is the zlib-ng `develop` branch at commit `5f1f4899` plus the patches below, applied in name
order. Every patch is **local and pending**: none has been submitted upstream yet. Each is replaced by the upstream
fix once one exists, and deleted once the pin moves past it.

| Patch | Files | What it changes | Defect it addresses | Confirmed on real C |
| --- | --- | --- | --- | --- |
| `0003-inflate-copy-pointer-equality.patch` | `inflate.c` | `inflateCopy` tests `state->lencode == state->codes` instead of a `>=` / `<=` range test. | The range test compares a pointer into the static fixed-code table with a pointer into the heap state (ISO C17 §6.5.8p5). | yes (pointer-pair check) |
| `0004-gzseek-overflow.patch` | `gzguts.h`, `gzlib.c` | `gzseek64` computes the target position with explicit range checks against `GZ_OFF_MAX`, and skips the buffer update when `n == 0`. | Signed 64-bit overflow in the offset arithmetic of `gzseek64` (`SEEK_CUR` adds the pending skip without a bound); `state->x.next += 0` on a never-set `x.next` when `gzseek` is called before the first read (wild pointer `+ 0`, ISO C17 §6.5.6p8). | overflow yes (UBSan); `x.next + 0` by the letter of the standard |
| `0006-deflatebound-gzip-extra-length.patch` | `deflate.c` | `deflateBound` adds `2 + (extra_len & 0xffff)` for a user gzip header with an extra field. | `2 + extra_len` is computed in 32-bit `unsigned` and wraps for `extra_len >= 0xfffffffe`, so the bound is below what one `deflate(Z_FINISH)` writes, against the promise of `zlib.h`. Not undefined behaviour. | yes (`deflate` does not return `Z_STREAM_END`) |
| `0007-inflate-window-copy.patch` | `inflate.c`, `inffast_tpl.h` | A match copied from the sliding window to the output is copied with `memcpy(out, from, n); out += n;` instead of `chunkcopy_safe` in state `MATCH` of `inflate`. In `inflate_fast`, each of the four window copies first tests `window == beg` (`beg` is the start of this call's output): when equal, the copy is upstream's `CHUNKCOPY_SAFE` / `chunkcopy_safe`, unchanged; otherwise it is the `memcpy` form. `inflate`'s window is its own allocation and its output the caller's buffer, so there `window != beg` and the copy is the `memcpy`: the copy length already fits the output (`copy <= left`; `inflate_fast` keeps 258 bytes of room, or bails out to `MATCH` in safe mode), and the ranges are in different objects, so the result is the same. `inflateBack` decodes into the caller's window and calls `inflate_fast` with `beg == window`: there both pointers are in the one window, the copy can overlap, and upstream's copy (which handles overlap) is used. Pointer equality is defined for any two valid pointers (ISO C17 §6.5.9p6), and since `beg` points to an element of the output (not one past its end: `inflate_fast` is called with room for at least 3 bytes), it equals `window` only when the output is the window. `infback.c`'s own `MATCH` is unchanged: its `chunkcopy_safe` / `chunkmemset_safe` compare two pointers into the window. | `chunkcopy_safe`, `CHUNKCOPY_SAFE` and `chunkmemset` compare (`>=`, `<`) and subtract a pointer into the window and a pointer into the caller's output, which point into different objects (ISO C17 §6.5.8p5, §6.5.6p9). | yes (pointer-pair check); `inflateBack` with the revised patch: no report |
| `0008-inflatesync-null-next-in.patch` | `inflate.c` | `inflateSync` advances `next_in` only when `syncsearch` consumed bytes. | With `next_in == NULL`, `avail_in == 0` and at least 8 primed bits, `strm->next_in += 0` is `NULL + 0` (ISO C17 §6.5.6p8). | by the letter of the standard on a traced run (no sanitizer reports `NULL + 0` in C) |
| `0009-inflatesetdictionary-null.patch` | `inflate.c` | `inflateSetDictionary` returns `Z_STREAM_ERROR` for a `NULL` dictionary, as `zlib.h` documents, before any other step. | `inflateSetDictionary(strm, NULL, 0)` on a raw stream computes `NULL + 0`, `NULL - 0` and calls `memcpy` from `NULL` (ISO C17 §6.5.6p8, §7.24.1p2), and returns `Z_OK`. | by the letter of the standard on a traced run; the return value differs (`Z_OK` vs `Z_STREAM_ERROR`) |
| `0010-inflate-fast-primed-bits.patch` | `inflate.c` | `inflate` (state `LEN`) calls `inflate_fast` only when fewer than 8 bits are held (`bits < 8`), which `inflate_fast` assumes; otherwise it decodes the code in `inflate` itself. Without `inflatePrime` fewer than 8 bits are always held there, so nothing else changes. | When `inflatePrime` has left 8 or more bits in the bit buffer, `inflate_fast` returns `bits >> 3` bytes of input on exit (`in -= len`, `inffast_tpl.h:327`), more than it read: `next_in` moves before the caller's buffer (ISO C17 §6.5.6p8), `avail_in` grows past what the caller gave and `total_in` wraps. | yes (`avail_in` and `total_in` after the call); no sanitizer reports the pointer itself |
| `0011-inflate-extra-copy-bound.patch` | `inflate.c` | `inflate` (state `EXTRA`) copies into `head->extra` only when `state->length <= head->extra_len`, and limits the count with `copy > extra_max - len` instead of `len + copy > extra_max`. For one stream that owns its header, `head->extra_len` is the length its own `EXLEN` stored, so the test holds and neither sum wraps: nothing else changes. | `inflate` assumes that `head->extra_len` is the value its own state `EXLEN` stored. When two streams share one `gz_header` (through `inflateCopy`, or a second `inflateGetHeader`), the other stream can store a smaller `extra_len`: `extra_len - length` and `len + copy` wrap, and `memcpy` writes past the end of `head->extra` (heap buffer overflow). | yes (AddressSanitizer heap-buffer-overflow) |
| `0012-longest-match-offset-base.patch` | `match_tpl.h` | `mbase_start` stays `window`: the two statements that moved it back by `match_offset` (`mbase_start -= match_offset; mbase_end -= match_offset;` after the lazy-evaluation search, `mbase_start = window - match_offset` after the offset search) are removed, and each of the six candidate addresses `mbase_start + cur_match` / `mbase_end + cur_match` becomes `mbase_start + (cur_match - match_offset)` / `mbase_end + (cur_match - match_offset)`. Wherever a candidate is read, `cur_match > limit = limit_base + match_offset` holds (every update of `match_offset` or `cur_match` is followed by that test or returns), so the subtraction does not wrap and the address, and every byte read, is the same as before: the output is unchanged. `longest_match_c` (levels 2-6) keeps `match_offset == 0`. | In `longest_match_slow_knuth_c` / `longest_match_slow_roll_c` (levels 7-9), `window - match_offset` points before the start of the block of `alloc_deflate` when `match_offset` exceeds the alignment padding before the window (ISO C17 §6.5.6p8); `match_offset` reaches 256. | by the letter of the standard on a traced run: a copy of `match_tpl.h` instrumented to compare `match_offset` with the window's offset in its block reports 224926 out-of-object base pointers over the `deflate` inputs of the differential test without the patch (window at offset 0, offsets up to 223) and, with the patch, 0 subtractions `cur_match - match_offset` that would leave the window; no sanitizer reports forming the pointer. The compressed output of every one of those inputs is identical with and without the patch. |
| `0013-deflate-medium-insert-count.patch` | `deflate_medium_tpl.h` | `deflate_medium` bounds its insert count: `max_insert_count = MIN(MAX(2, s->max_insert_count), STD_MAX_MATCH)`. For a count above 258 every match (at most 258 bytes) was already inserted position by position, by `insert_knuth_batch` or by `insert_knuth_stepped` stepping by one, so the output is unchanged except where the C divided by zero. | `max_insert_count` is `max_lazy_match`, which `deflateTune` stores as given. For `max_lazy = INT_MIN`, `max_len = 2 * max_insert_count` wraps to 0 and a match at distance 1 leaves one position to insert: `insert_knuth_stepped` divides by `inserts - 1 = 0` (ISO C17 §6.5.5p5; `SIGFPE` on x86_64). | yes (UndefinedBehaviorSanitizer division by zero, `insert_string_p.h:186`) |
| `0014-gzwrite-caller-buffer-pointer.patch` | `gzwrite.c` | On the direct path of `gz_write` (a write of at least the buffer size, compressed or transparent), when `gz_comp` fails, `strm.avail_in` is set to 0 and `strm.next_in` to `state->in` before `gz_write` returns 0; after the direct path succeeds, `strm.next_in` is set to `state->in` (`avail_in` is already 0 there: the direct `write` cleared it, and `deflate` with room left in the output consumed all input). On every path without a failure the stream then holds what it held before except a `next_in` that no code reads while `avail_in` is 0. | One stale pointer: the direct path points `strm.next_in` at the caller's buffer and left it there, with `avail_in` nonzero after a failed `write`. After `gzclearerr`, a small write (`gz_write`, `gzputc`, `gzprintf`) computed `(next_in + avail_in) - state->in` across objects (ISO C17 §6.5.6p9) and copied past the end of `in`; `gzclose` (`gz_comp(state, Z_FINISH)`), `gzflush` and `gzsetparams` wrote or compressed `avail_in` bytes of the caller's buffer after `gzwrite` had returned (use after free when the caller freed it). Both findings of a failed `gzwrite` are fixed by this one patch. | yes (pointer-pair check / heap-buffer-overflow; heap-use-after-free) |
| `0015-gz-buffer-alloc-null-offset.patch` | `gzlib.c` | `gz_buffer_alloc` tests the allocation (`state->in == NULL`) before it computes `state->out = state->buffers + in_size`; the second half of the old test (`out_size && state->out == NULL`) is dropped, as it is false whenever the allocation succeeded. | When the allocation failed, `state->buffers + in_size` was `NULL` plus a nonzero offset (ISO C17 §6.5.6p8). | yes (UndefinedBehaviorSanitizer, GCC and clang wording) |
| `0016-gzread-position-bound.patch` | `gzread.c` | The readers stop at the largest position: `gz_read` limits each step to `GZ_OFF_MAX - x.pos` bytes when `x.pos > 0` and returns what it has when that is 0; `gzgetc` takes a byte from the output buffer only while `x.pos != GZ_OFF_MAX` (otherwise `gz_read` returns 0 and `gzgetc` -1); `gzgets` limits its copy the same way and stops when no byte fits. Below `GZ_OFF_MAX` nothing changes. `gz_skip` needs no bound: `gzseek64` (patch 0004) keeps `x.pos + skip <= GZ_OFF_MAX`. The `gzgetc` macro of `zlib.h` runs in the caller and is not changed. | The readers added the bytes they delivered to the signed 64-bit `x.pos` without a bound: after `gzseek` to near `2^63` on a descriptor whose `lseek` succeeds and which keeps delivering data, `x.pos += n` overflowed (ISO C17 §6.5p5). | yes (UndefinedBehaviorSanitizer, `gzread.c:356`) |
| `0017-gzwrite-position-bound.patch` | `gzwrite.c` | `gz_write` refuses a write that would move `x.pos` past `GZ_OFF_MAX` (`len > GZ_OFF_MAX - x.pos`, after a pending seek is done) with `Z_DATA_ERROR` and the message "write position does not fit in z_off64_t", before it touches the caller's buffer; `gzputc` takes its buffer fast path only while `x.pos != GZ_OFF_MAX` (else `gz_write` refuses); `gzvprintf` refuses a formatted length above `GZ_OFF_MAX - x.pos` the same way. `x.pos` is never negative when writing, so `GZ_OFF_MAX - x.pos` does not overflow. Below that position nothing changes. `gz_zero` needs no bound: patch 0004 keeps `x.pos + skip <= GZ_OFF_MAX`. | The writers added each length to the signed 64-bit `x.pos` without a bound, before writing (a failed write keeps the addition): after `2^63` bytes in all, `x.pos += n` overflowed (ISO C17 §6.5p5). | yes (UndefinedBehaviorSanitizer, `gzwrite.c:210`, after about `2^32` failing `gzwrite` calls of `INT_MAX` bytes, 22 minutes) |

History of patch 0007: its first version copied all four window copies of `inflate_fast` with `memcpy`, assuming
that the window and the output are distinct objects. `inflateBack` calls `inflate_fast_safe` with its output inside
the caller's window, so there a match that reaches into the previous pass of the window (`dist + min(op, len) >
wsize`) made `memcpy` copy between overlapping ranges, undefined (ISO C17 §7.24.2.1p2; AddressSanitizer
`memcpy-param-overlap`). This was a defect of our patch, not of upstream, and is not a finding. The `window == beg`
test above fixes it; `tests/regression/infback-window-overlap` runs `inflateBack` on such streams (windowBits 8, 9
and 15, overlapping copies and `dist == wsize`) without the patch and with it, both clean, and keeps the first
version (`first-0007.patch` there) as a guard that must still show the overlap.
