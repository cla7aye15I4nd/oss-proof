# 规格：定理陈述了什么

这一部分用文字说明证明了什么，并指向确切的 Lean 命题。
本项目对默认 x86_64 Linux 构建中 zlib 每个有文档的公开函数证明一条性质，即**安全性**：
调用没有未定义行为，没有内存错误，会返回，只写它的命题点名的内存，并且不泄漏。
[安全性](safety.md)定义这四个子句，并用一个例子加以说明。

**目标**是关于一个函数或一个调用序列的 Lean 命题。这里的页面描述目标，不记录目标是否已经证明：
一个目标可以是已检查、已登记或已验收，这三个层级的定义见[术语表](../glossary.md#status)，
状态只记在[进展](../progress.md#scope)这一页。

API 页面和格式页面还描述每个函数返回什么、字节表示什么。那是功能行为。
它不是安全结论所必需的；已经证明的功能定理仍然保留。

## 确切的命题在哪里

确切的命题是 `ZlibF/Spec/` 下的 Lean 命题：

| 目录 | 内容 | 是否必需 |
| --- | --- | --- |
| `ZlibF/Spec/Safety/` | 流函数、校验和、查询函数和整缓冲区函数的安全目标。 | 是。 |
| `ZlibF/Spec/Public/` | 两类目标共用的定义：调用、历史、帧、分配账本。还有 gzip 文件接口和回调解码器的全部目标，安全目标和功能目标都在这里。 | 其中的安全目标是必需的。 |
| `ZlibF/Spec/Functional/` | 结果契约、格式模型和 API 模型，以及往返命题。 | 否；`Goal.compressBound` 和 `Goal.compressBound_z` 除外（见[安全性，附录](safety.md#where-the-goals-are)）。 |

`ZlibF/Spec/Api/` 和 `ZlibF/Spec/Format/` 只是重新导出 `ZlibF/Spec/Functional/` 下的模块；请导入新路径。
拆分的理由和导入规则见[拆分设计](../design/safety-functional-split.md)。
直接放在 `ZlibF/Spec/` 下的其他文件存放平台前提（`PlatformMemory.lean`），
以及证明用到的、关于内部辅助函数的命题。

[进展，目标证据](../progress.md#target-evidence)把每个目标链接到它的确切命题和证明它的定理。

## 文字与 Lean

这一部分的页面是文字说明。它们解释目标；它们不是目标本身。

- 页面与 Lean 命题不一致时，以 Lean 命题为准。
- 改动页面证明不了任何东西，也不会改变任何前提。只有类型与目标完全相同的定理才证明这个目标。
- 有些前提比 `zlib.h` 窄。每一条都明确写在目标里，并在[偏离记录](../deviations.md)中有一行。
- 关于内部辅助函数的引理，或关于某个固定配置的引理，证明不了公开目标。
