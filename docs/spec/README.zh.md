# 规范与证明目标

这里是规范参考。阅读模型与证明指南前，先查阅本节。

必需目标是安全性：默认 x86_64 Linux 构建中每个有文档的公开函数，都没有未定义行为、没有内存错误、没有泄漏，并且终止。
[安全性](safety.md)给出定义，并指向 Lean 目标。API 页面和格式页面还描述每个函数返回什么、字节表示什么。
那是功能行为：它不在计划的证明目标之内，已经证明的结果予以保留。
[进度](../progress.md)是当前状态与剩余工作的唯一记录。

## 建议阅读顺序

| 顺序 | 文档 | 回答的问题 |
| --- | --- | --- |
| 1 | [安全性](safety.md) | 必需目标陈述了什么：无故障、终止、帧性质和泄漏账本？它们在 Lean 的什么位置？ |
| 2 | [平台假设](platform.md) | 接受怎样的系统环境，包括每个对象的大小上界？ |
| 3 | [输入配置](input-configurations.md) | 覆盖颜色描述哪个固定构建下、怎样嵌套的输入范围？ |
| 4 | [API 契约](api/README.md) | 调用者可以传入什么，各入口返回或修改什么？它的安全目标是哪一个？ |
| 5 | [内部辅助函数契约](internal-contracts.md) | 实际调用者调用辅助函数前必须建立什么？ |
| 6 | [压缩数据格式](format/README.md) | 独立于实现，DEFLATE、zlib 和 gzip 字节表示什么？属于功能行为，不是必需目标。 |
| 7 | [格式关系](format/model.md) | 怎样用数学关系表达字节的含义？属于功能行为，不是必需目标。 |

API 页面描述入口行为。格式页面描述字节含义。两个引擎和所有公开入口共享安全性要求。
它们各自在这里有唯一的规范来源。

## 文档陈述与形式化陈述

精确陈述是 `ZlibF/Spec/` 下的 Lean 命题：

| 目录 | 内容 | 是否必需 |
| --- | --- | --- |
| `ZlibF/Spec/Safety/` | 安全目标。 | 是。 |
| `ZlibF/Spec/Public/` | 两类目标共用的定义：调用、历史、帧性质、账本。gzip 文件接口和回调解码器的目标也在这里，安全目标和功能目标都有：这些模块尚未拆分。 | 其中的安全目标是必需的。 |
| `ZlibF/Spec/Functional/` | 结果契约、格式模型与 API 模型，以及往返陈述。 | 否。 |

旧路径 `ZlibF/Spec/Api/` 和 `ZlibF/Spec/Format/` 是只有一行的转发模块，指向
`ZlibF/Spec/Functional/Api/` 和 `ZlibF/Spec/Functional/Format/`。
拆分的理由和导入规则见[拆分设计](../design/safety-functional-split.md)。
`ZlibF/Spec/` 顶层的其余文件是证明使用的内部被调函数契约。

[目标索引](../progress.md)将每个目标链接到精确陈述和证明证据。
文档契约解释这些目标。修改文字不能完成目标、改变其前提或赋予覆盖颜色。

部分前提比公开头文件更窄。每一个都明确写在目标里，并在[偏差记录](../deviations.md)中有一行。
范围较窄的内部引理不能建立公开目标。
