# Adler-32：有界求和与模运算细化

源代码是固定版本的 `zlib/adler32.c`，翻译为 `ZlibF/Zlib/adler32.c.lean`。数学契约是[格式指南](../spec/format/README.md)中的 `F-adler-incremental`。[API 页面](../spec/api/checksums.md)规定空缓冲区、包装函数与组合操作。

Adler-32 各函数在其文档规定的定义域上是安全的，并且返回 Adler-32 值。本页解释 `adler32_z` 的论证，其他入口都归约到它。

安全目标说的是：调用无故障地返回，并且堆完全不变。每条安全定理都是同一函数的完整契约去掉返回值之后的结果。因此下面关于值的论证是功能性的：它是早先证明的，继续保留，但只有其中的无故障部分是必需的。

## 假设了什么

缓冲区是 `len` 字节的可读范围，或者是 `NULL` 且 `len = 0`（`AdlerBufferBytes`）。`zlib.h` 还允许 `NULL` 配非零长度，此时 C 不读内存而返回 1。这一缩小在[偏差记录](../deviations.md)中有一行。组合函数没有前提：它们对每组参数都是安全的，包括伪造的校验和与负长度。

## 单字节递推

校验和用两个运行和概括已经读过的字节。`B = 65521` 是约减用的模数；`NMAX = 5552` 是两次约减之间最多处理的输入字节数。先把机器中的输入累加器拆成 `a = adler & 0xffff` 和 `s = (adler >> 16) & 0xffff`。这里 `a`、`s` 是机器中保存的两个分量，`α`、`σ` 是模 B 的数学分量；`b` 是下一个字节的数值，范围为 0 到 255。数学步骤为：

```
α' = (α + b) mod B
σ' = (σ + α') mod B
```

未约减的机器步骤是 `a' = a + b; s' = s + a'`。若机器求和未回绕，`a ≡ α (mod B)` 与 `s ≡ σ (mod B)` 可推出步骤后的相同同余关系。再模 B 约减即可恢复准确的数学数对。

因此证明分成两个不同的部分。安全部分：机器无故障地遍历正确的字节。功能部分：其求和在所述初值定义域上细化模递推。

## 读取与终止

输入指针由对象和对象内起始偏移 `off` 定位，`len` 是当前请求的字节数，`len₀` 是进入本次遍历时的初始字节数。若缓冲区非空，要求整个 `[off, off + len)` 范围可读。用 `k` 计数已经消费的字节，遍历不变量为：游标是 `off + k`，剩余数量是 `len₀ - k`，且 `k ≤ len₀`。每次读取时都有 `k < len₀`；每次指针递增最多到达末尾后一位置。

| 分支 | 消费字节 | 度量 |
| --- | --- | --- |
| `len == 1` | 一个字节 | 无循环 |
| `len < 16` | 字节循环每轮一个 | 测试前的剩余数量 |
| 完整批次 | `347 × 16 = 5552` | 剩余批次数和展开组数 |
| 尾部 | 先以 16 字节分组，再处理单字节 | 剩余数量 |

后减测试可能在最后一次失败测试时使局部无符号计数器回绕。证明准确建模这个测试；回绕值不代表又执行了一轮循环体。度量既给出数学终止，也满足翻译后的步数预算界限。

单字节快速路径在空缓冲区检查之前。初始化查询要求 `buf == NULL` 且 `len == 0`，不读内存而返回 1。其他调用要求可读的非空范围。该函数不写调用者内存，也不分配块。

## 默认构建的批次与无回绕界限

证明推迟约减安全，需要先界定机器整数在一个批次内能增长多少。用 `j` 表示自上次约减以来处理的字节数，范围为 0 到 5552。从 16 位分量出发，执行 `j` 步后可使用以下界限：

```
a ≤ 65535 + 255 j
s ≤ 65535 + j (65535 + 255 × 5552)
```

当 `j ≤ 5552` 时，得到 `a ≤ 1481295` 和 `s ≤ 8224215375`，均低于 `2^64`。默认 LP64 的 `unsigned long` 加法因此与普通自然数算术一致。这个宽松界限专用于 64 位论证；其他字长必须针对其分支建立合适界限。

16 字节展开把单字节不变量连续保持十六次。将它应用于各完整批次和尾部，然后约减，得到打包结果 `a | (s << 16)`。移位和打包也需要机器位宽界限。

## 准确的初值范围

正常的增量校验和从已约减的分量出发。但公开函数也接收整数累加器，正确性声明必须说明如何解释非规范分量。

短分支的低分量满足 `a ≤ 65535 + 15 × 255 = 69360 < 2B`，一次条件减法足以约减；高分量则模 B 约减。单字节分支对两个分量各只执行一次条件减法。以这种方式约减高分量，要求输入 `s < B`：新的低分量低于 B，两者之和才低于 `2B`。

因此，递推论证覆盖 `len ≠ 1` 时的任意累加器字（`adler32_z_correct_ne_one`），以及输入高分量低于 B 时的单字节情形（`adler32_z_correct`）。空缓冲区返回是单独的情形。安全性在每个分支中对每个累加器字都成立（`adler32_z_safe`）。公开的值目标 `Goal.adler32_z` 覆盖每个种子：它的规范 `adlerValue` 按 C 的实际计算描述单字节分支。

这个差异可以观察到。对于 `adler32_z(0xFFFFFFF0, "\0", 1)`，掩码后的低分量为 65520，高分量为 65535。字节步骤后的和是 131055，减一次得到 65534，函数返回 `0xFFFEFFF0`。完整模约减会使高分量等于 13。该调用内存安全；若规范对任意初值字都执行完整约减，就会给出不同结果。正因为有这个反例，公开的值没有陈述为完整模约减。

## 包装函数与组合

`adler32` 转换它的 32 位长度参数之后就是 `adler32_z`。

`combine` 函数需要单独的算术证明。它展开拼接时的两项运行和，加入初值修正，并说明翻译后的约减确实计算该公式。`adler32_combine_correct` 陈述了它：对字节串 `A` 和 `B`，`|B| < 2^63` 时，从初值 1 出发有 `adler32_combine64(adler32(A), adler32(B), |B|) = adler32(A ++ B)`。`adler32_combine_safe` 表明这些函数对每组参数都不产生故障。负长度返回文档规定的哨兵值。
