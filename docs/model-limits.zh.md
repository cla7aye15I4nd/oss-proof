# 模型的限制

本页列出模型的一类限制：zlib 的调用者对它们无法采取任何行动。它们分三类：目标作为前提陈述的、对模型中的堆的条件；运行时表示 C 的内存和库调用时所作的选择；以及功能定理和模型定理的限制，必需的安全目标都不依赖它们。调用者的义务在另一页：[偏离记录](deviations.md)。被信任的东西概括在[可信基础](trusted-base.md)中，本页是其中第 2 项的细节。

每一条限制都是模型可能与 C 不同的地方。任何一条都不是悄悄收窄公开定理的许可。

## 本页用到的名字

| 名字 | 含义 |
| --- | --- |
| 块 | 模型的堆中的一次分配，用一个编号指称 |
| `nextBlk` | 下一次分配将得到的编号。释放之后编号不会再用 |
| `Fresh` | 编号在 `nextBlk` 及以上的块都不存活 |
| `Uniq` | 一个块编号至多在堆的一张表中存有对象 |
| `allocOk` | 分配预言：对每一次分配尝试，说它是否成功 |
| `Heap.garbage` | 任意初值函数：新分配内存中每个整数单元的值 |
| `Tbl` | 堆中表的类型：一个数组，按块编号当作全函数来读 |
| `Space.get`、`put`、`modify` | 读堆中的一个数组、替换它，或就地修改它 |
| `copyK` | 整个记录的复制，即对一个结构体做 `memcpy` 的模型 |
| `strLitRef` | 指向一个 C 字符串字面量的指针 |

## 目标所陈述的、对模型的条件

这些行是目标的前提。C 程序什么都不用做就满足其中每一条；它们之所以存在，是因为 Lean 命题要对模型中的每个堆量化，其中包括任何 C 程序都造不出来的堆。

| 领域 | 目标陈述了什么 | 后果 |
| --- | --- | --- |
| 堆的良构性（`Fresh`、`Uniq`、`LibraryGlobals`、`CrcGlobals`） |初始化、打开、`compress*` 或 `uncompress*` 调用开始时的堆，在 `nextBlk` 及以上没有存活的块（`Fresh`），每个块编号至多有一个对象（`Uniq`），并且带有所选构建的常量表（`LibraryGlobals`）。CRC 目标只要求两张 CRC 表（`CrcGlobals`），`inflate` 的拒绝只要求 `Fresh`。两次调用之间调用者的修改保持这三条（`Rebuffer`、`GzCallerFrame`）。 | 这些是对模型中的堆的条件，不是 `zlib.h` 加给调用者的义务，但它们仍然是前提。`Fresh` 并不说 `nextBlk` 以下的块编号在各表之间唯一；`Uniq` 才说这一点。 |
| 循环燃料 | 翻译后的每个循环至多运行 `2^64` 次迭代；耗尽这个上界就是 `Fault.outOfFuel`。 | 结论为正常返回的安全目标证明了这个上界永远达不到。凡是 C 可能无界地循环、而证明又推不出上界的地方，目标都带有一条给出上界的前提：[回调输入总量](deviations.md#callback-decoder)和 [gz 读取预算](deviations.md#gzip-file-interface)。 |
| CRC 地址与字访问 | `addrOf` 只观察地址的低位。堆字节块沿用起点对齐的约定；静态的和内嵌的字节对象有任意而稳定的余数。字的加载是按字节拼出来的。 | 通用的 ABI 布局、任意的原始块起点，以及 C 强制转换的别名语义，都不在这个抽象之内。公开的校验和定义域不受影响。[静态地址回归](../tests/verification/regressions/crc-static-address.lean)保留了模型早先一个反例的输入，作为正向检查。 |
| NULL 指针算术 | `Ptr.add` 允许 NULL 加零；`Ptr.diff` 遇到 NULL 就出故障，而压缩器的辅助函数 `Compress.ptrDiff` 允许 NULL 减 NULL。 | 模型允许，不等于 C 有定义。[安全性规格](spec/safety.md#null-pointers-and-pointer-differences)区分了这些操作和语言规则。[分配回归](../tests/regression/compress-allocation/README.md)为零容量的 NULL 目的缓冲区保留了这一区别。 |
| 外部错误字符串 | `strerror` 返回一个只读视图，视图上带有一个代次，每次 `strerror` 调用都会改变这个代次。它不消耗分配尝试，也不占用库拥有的存活块。下一次 `strerror` 调用使先前的视图失效。 | 模型选取的是顺序调用和固定区域设置下的文本。并发调用、区域设置的改变，以及旧指针身份的再次使用，都在模型之外。复制文本与保持借用是两项独立的证明义务。这不是与 libc 的完整对应。 |

## 运行时怎样表示 C

`ZlibF/Runtime/` 定义了翻译后的一次运行是什么意思，所以“不出故障”的定理说的就是这些定义。下面两张表列出审查者必须知道的选择。

### 内存与库操作

堆为每一类对象单设一张表。释放过的块编号永不再用。分配器只有在 `nextBlk` 这个编号在每一张表中都尚未使用时才写入（`Heap.slotUsed`），否则出故障。`Fresh` 保护将来的编号。初始的堆还必须让 `nextBlk` 以下的块编号在各表之间唯一；单靠 `Fresh` 表达不了这个条件，`Uniq` 可以。

| 操作 | 需要审查的模型行为 |
| --- | --- |
| `memcpy`、`zmemcpy` | 即使长度为零也拒绝 NULL 指针，并拒绝重叠的范围；长度不为零时拒绝只读的目的地址。整个记录的复制使用 `copyK`，它拒绝把对象复制到自身上。单独的一次记录读取加一次记录写入，不检查重叠。 |
| `memmove` | 检查同样的范围和可写性（长度为零时同样例外），但允许重叠，并从原来的源复制。 |
| `memset`、`zmemzero` | `Ptr.fill` 按元素计数并赋一个值；即使长度为零它也拒绝 NULL 指针，长度不为零时拒绝只读的目的地址；只有在指明的用法里它才表示按字节的 `memset` 或清零。`Ptr.memset` 重复一个字节。整个记录的清零是写入一个显式的零记录。 |
| `strlen` | 要求所表示的块内有 NUL。 |
| 分配 | 新分配的整数来自任意初值函数；新分配的指针字段是 NULL。超过 `PTRDIFF_MAX` 字节的 `malloc` 请求返回 NULL。否则由预言 `allocOk` 决定是否失败。每次 `malloc` 调用消耗一个预言编号。自动局部对象绕过这个预言，不消耗分配尝试。 |
| `free` | NULL 是空操作。否则参数必须指向对应种类的一次存活、可写的分配的起点。没有记录分配来源的标签。 |
| 字符串字面量 | `strLitRef` 指称生成的封闭表 `strTable` 中一个静态、只读、以 NUL 结尾的条目。它始终存活，身份稳定，永不释放。表中没有的字面量文本会出故障。借来的外部错误文本另有自己的只读视图和生命周期。 |

运行时和翻译只为它们用到的外部操作提供特定的模型，而不是通用的 libc 模型。运行时的错误文本和 gzip 的外部辅助操作实现的，就是上面“外部错误字符串”一行所说的固定区域设置、顺序调用下的借用视图行为。分配、格式化、`errno` 和 `abs` 也需要各自的对应关系审查；它们放在 `Runtime/` 之外，并不降低它们在语义上的分量。

### 表示上的缺口与证明义务

| 选择或缺口 | 对关于 C 的结论的影响 |
| --- | --- |
| 未初始化指针变成 NULL | 对 NULL 的相等比较、复制和释放，可以在没有先写入的情况下成功。每一次指针读取都需要一个“先写后读”的论证。初始化的翻译显式地把分配出来的两种流状态记录清零；这并不是新分配记录或自动变量 `z_stream` 存储的普遍性质。要补上这个缺口，需要跟踪初始化，或者为所有形式的指针引入一个单独的“未初始化”值，并配上带检查的操作和相应的翻译修改。 |
| 每个单元一个任意初值 | 关于整数的定理对每个 `Heap.garbage` 量化，它以分配尝试和单元位置为下标。但对同一个单元的多次读取结果仍然一致。在 C 允许未指定的值不稳定的地方，证明不得依赖这种一致。 |
| 数组的范围是谓词 | `WellFormed`、`Heap.RecordsWellFormed` 和 `Statics.WellFormed` 必须确立 C 中的长度。生成的保持引理保留它们。静态内容必须与定义它们的 C 翻译相符；运行时不把它们与 C 作比较。 |
| 指针相等是结构相等 | 不同对象比较为不等；悬空指针的相等比较不出故障。证明不得依赖 C 不保证的结果，包括相邻对象边界处的相等。关系比较要求两个指针在同一个存活的数组里。 |
| NULL 指针算术部分被允许 | `Ptr.add NULL 0` 返回 NULL。`Ptr.diff` 拒绝 NULL 参数，而 `Compress.ptrDiff` 对两个 NULL 返回零。这些选择都需要对相应的 C 调用另作“有定义”的论证。源码中 `Ptr.diff` 的注释把 NULL 指针相减归到 C23 名下，这并不准确；见[操作与语言对照](spec/safety.md#null-pointers-and-pointer-differences)。 |
| 地址与布局模型不完整 | 没有通用的 ABI 地址、有效类型或“记录的字节视图”模型。CRC 观察地址的低位：堆字节块沿用对齐的起点；静态的和内嵌的字节起点有任意而稳定的余数。这些余数是堆的元数据，不是可写的字节：任何写入都不改变它们。按字节拼出的字加载，不能定论 C 强制转换的别名语义。标量单元的适配器可能略去别名；有八个公开函数的结果单元是值而不是内存（[偏离记录](deviations.md#stream-calls-inflate-and-deflate)的“结果单元”和“整缓冲区压缩”两行）。`z_stream` 记录放在单独的表里，所以与缓冲区或另一个记录部分重叠的记录无法表达（[偏离记录](deviations.md#stream-calls-inflate-and-deflate)，“复制的目的流”一行）。 |
| 只读标记不完整 | 字节块、具名的静态表和实例可以是只读的。字块和表中的记录无法表示这个限定。 |
| 指针构造的检查不完整 | `Ptr.add` 检查它的结果，但不检查手工构造的起始偏移是否有效。翻译审查必须排除对公开构造器 `Ptr.ref` 的无效使用。 |
| 不跟踪对象的来源 | 由 `allocBytes` 创建的调用者块可以被翻译后的代码释放。在 API 禁止这样做的地方，必须由帧子句和所有权子句来防止。把状态当作错误种类来访问，会比相应的 C 访问更早出故障。 |

[运行时审查](checking/runtime-review.md)是关于这些选择的历史证据，不是对当前定义的独立认可。

### 表的更新

`Tbl` 包着一个数组，按块编号当作全函数来读。不存在的条目返回默认值（`none` 或 `false`）。更新操作 `upd` 有已证明的同键、异键和重复更新规则，它们来自 `Tbl.get_set`。

执行写入的原语使用 `Space.modify`：它把数组从表中取出，修改后放回，这样就不会留下一串旧数组。`Space.modify_eq` 说它等于更简单的函数式操作 `put`。可信审查必须覆盖 `Tbl.get_set`、`Tbl.modify_eq`，以及每个生成的 `Space` 实例的 `modify` 和 `modify_eq`。操作引理是用 `put` 来推理的；可执行程序跑得快，并不能确立两者的对应。见[表更新审查](checking/runtime-tables-review.md)。

## 功能命题与模型命题

下面各行限制的是功能目标、API 模型和内部引理。必需的安全目标都不依赖它们。它们仍然列在这里，是因为它们所限制的定理保持登记。安全结论不需要功能目标（[范围](progress.md#scope)）。

| 领域 | 目前的限制 | 后果 |
| --- | --- | --- |
| 针对单个函数的手册条目 | 条目可以要求有效的句柄、互相分离的缓冲区、实际字符串的校验和、生成的算子，或某种写明的调用顺序 | 这些是用文字写明的范围，并不缩小更宽的 Lean 公开目标。 |
| API 模型中压缩器的长度单元 | 功能模型 `Concrete.compress2_z` 和 `Concrete.compress2` 使用一个可选的标量输入和一个返回的存储值 | 这一行只关乎功能模型。那里没有“单元与输入或输出重叠”这回事。`_z` 形式与兼容包装函数对 NULL 单元的效果仍然不同。翻译用的是同样的标量单元，这确实限制了必需的安全目标：见[偏离记录](deviations.md#whole-buffer-utilities-and-checksums)中“整缓冲区压缩”一行。 |
| 计数解压的单元 | 草稿适配器让输入长度、输出长度和数据范围保持分离 | 单元与数据重叠或单元互相重叠，都在这些适配器之外。早期与晚期的内存失败保留各自不同的标量效果。 |
| 压缩器的数据关系 | `Compress2` 用一个粗粒度的拒绝标志来描述数据 | `Compress2Z` 和 `Compress2Wrapper` 表达指针的形态、错误的先后顺序和长度的写回。单有数据模型的定理，并不是入口函数的细化。 |
| 上界的算术 | 在 LP64 上两个长度都是 64 位 | `Goal.compress_bound_value` 覆盖每个 `UInt64`，没有更小的数值前提。其他 ABI 需要关于大小转换的命题。单有数值公式，并不说明输出空间足够。 |
| deflate 字典的顺序 | `DeflSetDict` 的 zlib 分支在 `started` 之后拒绝字典 | C 可以在流结束之后接受字典。细化只能在有文档的顺序之内使用这种拒绝。`deflate_valid` 是一条模型定理，不是关于所有这类 C 执行的定理。 |
| 普通字节格式的各个阶段 | 一个普通的流由一份初始的预设字典来解释 | 解码开始之后在裸流上替换字典，有一个由构造子导出的标记。它对窗口的确切影响是一个功能命题，不在计划内。这类历史的序列安全性已经证明：`Goal.inflate_sequence_safety` 已登记，并覆盖历史中任何位置上的 `inflateSetDictionary`。单独一份初始字典描述不了整段高级用法的历史。 |
| 高级操作的组合 | 预置比特、头部和恢复各自保留具体的、按条目划分的目标 | 这组目标并不是对每种组合的完整操作性细化。证明不得为了回避义务而选择或清除历史上的资格标记。 |
| 快速解码辅助函数 | 局部的执行引理和比特来源引理假设：输入和输出是原始字节块（不同的块，或同一块中不相交的范围），窗口所在的块不是输出块，有六个输入字节、258 个输出字节，进入时的比特数小于八，并且处于 `sane` 模式 | 这些是内部前提，由构造和初始化的不变量来确立。它们既不限制、也不证明公开的 inflate 目标。 |
| 窗口参数被接受时的 inflate 初始化 | `inflate_init2_valid_public` 假设 `Api.inflWbits wb.toInt = some (wrap, bits)` | 对被接受的裸、zlib、gzip 和自动检测窗口参数，它保留现有的初始化契约，包括所有分配结果、ABI 与版本的拒绝，以及 NULL 流的拒绝。无效的窗口参数被显式排除；`Goal.inflateInit2_` 的命题及其记录在案的清理契约问题没有变化。 |
| Gz 文件数据 | 功能性的 gz 契约（`FileData`、`CloseContract`、`GzWriterFormat`、读写的值），以及已登记的目标 `Goal.gzoffset64`、`Goal.gzoffset` 和 `Goal.gzrewind`（前提 `RegularOs fs`），都是针对“每个系统调用都按普通文件行事”的世界（`RegularOs`）陈述的 | 它们描述的是普通文件。预言的 `lseek` 可以返回而不移动描述符，某些 Linux 设备就是这样；在那里，偏移值和倒回的结果不成立（[回归](../tests/verification/regressions/gz-offset-regular-world.lean)）。安全目标不使用这些契约。`gzoffset64`、`gzoffset` 和 `gzrewind` 在每个世界上的安全性是 `Goal.gz_sequence_safety` 的一部分，该目标已登记，没有 `RegularOs` 前提。文件系统的权限、父目录、链接、属主和加锁都没有表示；它们对每次调用的影响由预言的失败来涵盖。 |

中间 deflate 定理的前提，以及局部的打开、关闭和预置比特引理的前提，收窄的是引理，从不是公开目标。它们保存在[deflate 内部证明范围](history/deviations-internal-scopes.md)中。
