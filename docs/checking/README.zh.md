# 完成的结论依靠什么

[状态页](../progress.md)把一项结论称为完成，是指存在一条 Lean 定理，它的命题恰好就是这个目标，并且通过了本项目的每一项检查。本页说明这意味着什么：一项完成的结论有四件事成立，而其中没有一件证明了 Lean 文本正确地描述了 C。

## 一项完成的结论有哪些事成立

1. **Lean 内核检查了证明。** 内核是 Lean 核心的一个小程序，它接受或拒绝一个证明项。没有任何证明使用 `sorry`、`native_decide`，或者其他不经内核检查就直接采信结果的构造。
2. **只使用三条标准公理。** 证明和它依赖的一切，除 `propext`、`Classical.choice` 和 `Quot.sound` 之外不使用任何公理。没有为本项目添加公理。
3. **定理的类型恰好就是目标。** 目标是一个 Lean 定义，定义的是一个命题，它与证明分开书写。使目标完成的那条定理，类型就是这个命题，不是更弱的命题，也不是相近的命题。范围更窄的引理不算数。
4. **前提写在命题里。** 一条定理写明它用到的每一个前提。前提比 `zlib.h` 允许的范围窄的地方，都列在[偏离记录](../deviations.md)中。

## 不是证明的证据

这些定理说的是 C 的一份 Lean 翻译，翻译是手工逐语句完成的。差分测试在许多输入上把这份翻译与真实的 C 作比较，带 sanitizer 和不带 sanitizer 都运行。它们是忠实性的证据，不是证明。

## 信任什么

一项完成的结论是否说出了关于真实 zlib 的事实，还取决于内核不检查的东西：Lean 内核本身、内存与故障的运行时模型、手工翻译、选定的源码及其补丁、外部世界的模型，以及各个目标的命题。[可信基础](../trusted-base.md)逐项列出它们，并说明相信每一项的理由。[模型的限制](../model-limits.md)列出模型可能与 C 不同的地方。
