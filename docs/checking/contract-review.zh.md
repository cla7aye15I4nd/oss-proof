# 公开契约审查记录

> **带日期的记录。** 这次审查写于 2026-11-06，当时项目的目标是为默认构建的 95 个入口和八个族级目标证明完整的功能契约。自 2026-11-11 起，范围只包括安全性（见[范围](../progress.md#scope)）：这里描述的契约是功能目标，不是必需的。其中已经证明的仍保持登记。规格文件后来移动过位置：格式模型和 API 模型在 `ZlibF/Spec/Functional/` 下，安全目标在 `ZlibF/Spec/Safety/` 下，`ZlibF/Spec/Public/` 存放公共定义（见[拆分设计](../design/safety-functional-split.md)）。下面各表中的模块名是审查当时的名字。这些更正和反例作为关于命题的证据仍然有效；每个更正后的命题今天是否已被证明，只由登记表和[进度页](../progress.md)回答。

这份记录说明这些契约背后的源码审查和反例。它不是对某个语义基线的独立批准。

## 三层规格

| 层 | 含义 |
| --- | --- |
| `ZlibF/Spec/Format` | 合法的 DEFLATE、zlib 和 gzip 字节，解码与校验和。 |
| `ZlibF/Spec/Api` | 不涉及堆的 API 模型。一些较早的模型只覆盖文档所述的调用模式。 |
| `ZlibF/Spec/Public` | 固定的实现目标：实际执行、调用者定义域、结果、帧性质和所有权。 |

`Calls.lean` 固定实际的翻译后的入口。公开目标不能把它换成空的执行关系，也不能假设库中被调用的函数满足其规格。只有格式层或抽象模型上的证明，并不验证一个公开函数。

## 源码审查的更正

审查在目标命题中辨明了以下区别：

- `Uncompress2` 允许在后期内存失败之前已有输出。它与具体的实用函数目标共用数据关系。缓冲区耗尽并不意味着未用的尾部字节能延续成一个有效流。初始化失败时长度单元可以保持不变；之后的失败则存入计数。
- 流查询包括对 NULL 的拒绝和对无效状态的不留痕迹的拒绝。位预置遵循源码中零、负数和溢出的判断顺序。可选的输出单元各自独立地可选。
- 固定的 `gz_look` 首先检查四个头部字节。错误的方法、标志，或更短的文件，都可能选中透明输入。之后的成员直接交给 inflate。默认缓冲区是 8192 字节；`gzbuffer` 把大小下限钳到八，并拒绝加倍时溢出的大小。格式化被拒绝时返回流错误，这与结果为空或过大是分开的情形。
- 头文件没有承诺 `gzsetparams` 会拒绝每一个无效的标量。对有效的参数，成功的调用既更新外层字段，也更新内部的压缩器。
- 回调描述符可以与窗口共用一次分配。它们保持窗口切片不变；它们的观察不变量只忽略这一切片。整函数目标对这些不变量全称量化，所以选一个宽松的不变量并不能完成它。

以上是对所选 C 的解读，**尚未由证明确认**，须由完整的实现证明确认。它们出现在编译通过的命题里，并不说明这些命题是完整的。

## 旧命题的反例

独立的后续审查把不可变的提交 `a655458` 作为旧规格。它没有改变公开的调用者定义域、翻译后的函数或运行时操作。

| 输入或状态 | 旧命题的错误 | 更正与记录下来的证据 |
| --- | --- | --- |
| 裸字节 `73 04 42 00`，一个输出字节 | 实际的第一次调用在取入一个不可能的距离之后，返回 `Z_OK` 和 `A`。“全部预读内容有效”的要求拒绝这个结果。 | 要求存在一个有有效补全的支持位前缀，并要求每个相容的补全都延续这段输出。一个内核证明否定了旧子句，并检查了一个模型见证。成对的 C 与翻译回归测试包含随后的 `Z_DATA_ERROR`。 |
| 有效的 gz 读取者，已分配的消息，空的只读表 | `dropWindow` 存入只读表的默认值，从而改变了该表的大小。实际的 `freeB` 不改变这张表。 | 只删除字节块。一个通用定理覆盖每个 `WindowAllocation`；完整的 `gzclearerr` 公开证明检查更正后的目标。 |
| 有 `2^63` 个解码表槽位的模型状态 | 查询视图漏掉了固定的 C 数组布局，从而允许超出 `ptrdiff_t` 的指针相减。 | 要求实际的 1444 项 `codes[ENOUGH]` 布局。一个内核反例保留了原来的问题；一个类型完全相同的公开 `inflateCodesUsed` 证明检查这一更正。 |

关于输出因果性的更正也适用于共用的 `Uncompress2`。在预读内容畸形之后，仅有全称的确定性可能是空洞的。两个更正后的子句都不假设剩余的预读内容有效。解码器模型的问题没有变：它仍需要细化到实际的解码器执行。另一条遗留的、关于固定检测延迟的子句有反例；这份记录不把那个模型当作已批准的实现细化。

清理辅助函数由 `inflateReset`、`inflateReset2`、`gzrewind` 和 `gzclearerr` 共用。它们分配的块是可写的，需要同样的字节块删除。通用的效果证明并不证明每个调用者。这是规格在表示上的错误，不是上游缺陷。

查询的布局来自 `inflate.h` 和 `inftrees.h` 中 852+592 的上界。已有的 `Good` 不变量蕴含它。初始化和实际的状态转移必须确立并保持这个不变量；序列目标把它作为结论来要求。没有增加任何公开的标量限制。

deflate 目标还在状态存活的前提下，固定了流错误分类的两个方向：无效的刷新值、无效的 NULL 缓冲区，或在结束已经开始之后的非结束调用。只列出允许的错误码，会容许无端的拒绝。写入消息的拒绝与更早的无效刷新值返回不同；只有后者承诺堆不变。

记录下来的模型变异体去掉因果证据、恢复“全部预读内容有效”的要求，或去掉输入前缀的要求。公开的 `gzclearerr` 变异体漏掉错误清除，或保留 EOF 标志。它们被拒绝，检验的是证明的敏感性。差分比较仍然只是有限的执行证据。

## 高级操作的边界

序列安全和清理包括所有被允许的操作，重置、复制和恢复也在内。普通的数据时期把实际接受和产生的字节与独立的格式联系起来，并包括空间足够时的完成。资格标记由轨迹的构造子计算；证明不能随意选择或清除它们。

一个初始字典描述的是一个普通的 RFC 流。中途替换裸解码器的字典会改变这一上下文。标记记录这一变化；它对每个入口的窗口效果以及序列安全仍然是必需的。位预置、头部捕获和恢复也保留各自具体的操作目标。这组目标还不构成对每种高级组合的完整操作细化。这条边界并不免除它们的安全义务。

gz 写入者的历史记录实际的调用、已接受的输入和已消耗的定位零。最后的关闭必须产生解码后等于这些数据的 gzip 成员；在透明模式下，则产生相同的字节。文件中已有的前缀和尾部都计算在内。只关于位置的契约是不够的。

## 审查与批准

提出更正一个命题时，需要不可变的旧命题和新命题、与 C 及手册的对照，以及对那个不成立的问题的解释。要分清四种情况：证明技术的问题、错误的规格、翻译不一致和上游缺陷。内部不变量的反例不能成为缩小公开前置条件的理由。任何替换的不变量都必须由初始化和此前的调用确立。被调用函数的契约仍然是已证明的结果。

已确认的规格错误在单独的一次改动中更正，它的反例作为回归测试保留。就绪检查查看的是是否存在、能否编译和全新重放；它不能判定语义上是否完整。公开定义域、表示上的限制和运行时，必须由审查批准。
