# 术语表

每个术语只定义一次，按读者需要的顺序排列。状态用语背后的规则见[检查指南](checking/README.md)；当前状态见[进度](progress.md#scope)。

## 目标

**目标（goal）。** `ZlibF/Spec/` 中关于一个 C 函数或一个调用序列的 Lean 命题，名字以 `Goal.` 开头。只有类型与它完全一致的定理才算证明了它。英文的 target 与 goal 是同一个意思。

**安全目标。** 陈述一次调用不出故障地返回（没有未定义行为，没有内存错误，并且终止）、只写自己的帧、不泄漏的目标。大多数命名为 `Goal.<函数名>_safety`。

**功能目标。** 陈述调用结果是什么的目标：返回值、输出字节、与数据格式的关系。自 2026-11-11 起功能目标不在计划内；已证明的仍保持登记。

**序列目标。** 关于同一个流或句柄上每一种调用序列的目标，例如 `Goal.inflate_sequence_safety`。它陈述不变量在每段历史之后都成立，并且再做一次调用仍然安全。

**历史。** 一个流或句柄上迄今发生的调用，从它的初始化或打开调用开始，包括调用之间调用者所做的修改。序列目标对每段历史作全称量化；历史用归纳谓词定义（`StreamReachable`、`GzHistory`、`BackSafeReachable`），不假设任何先前调用的规格。

**拒绝。** C 以错误值拒绝的调用，例如对 `NULL` 或不一致的流的调用。拒绝目标（`Goal.inflate_refusal`、`Goal.deflate_refusal`、`Goal.gz_refusal`）陈述这个值，并陈述调用不改变其他任何东西；唯一的例外是被拒绝的复制，它会清空目的流的状态指针。

**非空性目标。** 表明其他目标的前提能够被满足的目标：给出一个具体的堆，在其上初始化或打开成功，并得到一个可达的流或句柄。没有它，序列目标可能只因为不存在任何历史而成立。

**必需目标。** 验收审计坚持要求的目标：目标构建中每个有文档函数的安全目标，以及非空性目标。这个集合由 `tests/audit/public-api.json` 固定。

## 状态

**已检查。** 定理在 `dev` 上，且该提交上快速关卡为绿。Lean 内核已检查过证明。`AGENTS.md` 在这一级的措辞里写的是 `main`；实际做法是日常工作合并到 `dev`，`main` 在里程碑时接收 `dev`。

**已登记。** 定理列入 `tests/audit/theorems.txt`，它的目标列入 `tests/audit/proved-goals.txt`。

**已验收。** 定理已登记，且验收套件在某个具名提交上全部通过。只有已验收的结果才可以作为最终结果报告。

**未完成。** 还没有同类型已登记定理的目标。

**不在计划内。** 项目不做的目标，从不称为已证明。

## 模型

**故障（Fault）。** 模型中不能正常返回的运行的结果。C 能到达的每个未定义行为都引发 `Fault.ub`；循环上界耗尽引发 `Fault.outOfFuel`。安全定理证明没有任何运行会引发这两者，除非定理另有说明。

**堆与指针。** `ZlibF/Runtime/` 中的内存模型。新内存中的指针是 NULL。证明要说明指针字段在读取之前已被写入。

**可信基础。** 证明所依赖而内核不检查的部分：运行时、手工翻译、选定的源码、外部世界的模型。见[可信基础](trusted-base.md)。

**前置条件、前提。** 定理对输入的假设。

**偏离。** 比 `zlib.h` 允许的范围更窄的前置条件。它写在定理的文档注释中，并列入[偏离记录](deviations.md)。

**分离前置条件。** 调用者的各个内存区域彼此不重叠，也不与流拥有的存储重叠。定理把它写成假设。

**表示不变量。** 每次调用都保持的流状态性质，例如压缩流的 `DGood`、解压流的 `Good` 和 gz 句柄的 `GzInv`。由初始化或打开函数建立。

**`StreamBuffers`。** 关于 `next_in`、`avail_in`、`next_out`、`avail_out` 的假设。每个范围或为 NULL，或可读（输出范围可写）；两者都不在流自己的存储内；两个范围互相分离。安全目标中的每次 `inflate`、`deflate` 和 `deflateParams` 调用都以它为前提。

## 检查

**差分测试。** 用同一输入分别运行真实 C 与 Lean 翻译并比较结果。它是忠实度的证据，不是证明。

**证明变异体。** 故意写错的翻译，例如去掉一个检查。健全的证明必须在它上面失败。

**快速关卡。** `build` 与 `no-sorry` 两个任务，每次推送和拉取请求都运行。

**验收套件。** 公理关卡、目标精确匹配、自测、证明变异体和差分测试。每晚在 `main` 上运行，也可按需运行。

**里程碑。** `inflate` 证毕、`deflate` 证毕、一个序列目标证毕，或约二十个新检查通过的目标。
