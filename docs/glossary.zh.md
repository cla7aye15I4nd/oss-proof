# 术语表

本页定义其他页面用到的术语，每个术语只定义一次，用一两句话说清。术语分为几组：目标、状态层级、模型、前提、gzip 文件世界和检查。状态层级背后的规则见[检查指南](checking/README.md)；每项结论处于哪个层级，见[进度页的“范围”一节](progress.md#scope)。

## 目标

**目标（goal）。** `ZlibF/Spec/` 中关于某个 C 函数或某类调用序列的一个 Lean 命题，名字以 `Goal.` 开头。只有类型与目标完全相同的定理才算证明了它。英文页里的 target 是同一个意思。

**安全目标。** 这类目标说：调用正常返回而不出故障（没有未定义行为，没有内存错误，并且终止），只写它获准写的内存（它的帧），并且不泄漏。多数安全目标名为 `Goal.<函数名>_safety`。

**功能目标。** 这类目标说调用的结果是什么：返回值、输出字节、与数据格式的关系。安全结论并不需要功能目标；已经证明的功能目标保持登记。

**序列目标。** 关于同一个流或句柄上每个调用序列的目标，例如 `Goal.inflate_sequence_safety`。它说：每段历史之后不变量都成立，再做一次调用也是安全的。

**历史。** 在同一个流或句柄上至今做过的调用，从 init 或 open 调用开始，中间夹着调用者在两次调用之间所做的修改。序列目标对每段历史量化；历史用归纳谓词定义（`StreamReachable`、`GzHistory`、`BackSafeReachable`）。任何先前调用的规格都不被当作假设。

**可达。** 一个流可达，是指有某段历史产生了它：一次成功的 init，然后是任意多次调用和调用者修改。对应的 Lean 谓词是 `StreamReachable`；流函数的单函数安全目标在每个可达的流上成立。

**拒绝。** C 以错误值驳回的调用，例如对 `NULL` 流或不一致的流的调用。拒绝目标（`Goal.inflate_refusal`、`Goal.deflate_refusal`、`Goal.gz_refusal`）给出这个返回值，并说明调用不改变其他任何东西；唯一的例外是被拒绝的复制，它会清空目的流的状态指针。

**非空性目标。** 这类目标说明其他目标的前提可以被满足：存在一个具体的堆，在它上面 init 或 open 成功，并得到一个可达的流或句柄。没有它，序列目标就可能只是因为不存在任何历史才成立。

**见证。** 非空性目标给出的那个具体的堆（对 gz 还有具体的文件系统），例如 `ZlibF/Spec/Public/Domains.lean` 中的 `witnessHeap`。

**有文档的函数。** `zlib.h` 在注释 `undocumented functions (not part of the zlib API)` 之前声明的函数。该注释之后的十个函数是无文档函数，不要求它们各有自己的目标。其中的 `gzvprintf` 仍是 gz 序列目标里的一种调用，因为 `gzprintf` 要经过它。

**必需目标。** 验收审计坚持要求的目标：目标构建中每个有文档函数的安全目标、清单列出的序列目标和拒绝目标，以及非空性目标。这个集合由 `scripts/verification.py` 根据清单算出。

**清单（manifest）。** 文件 `tests/audit/public-api.json`。它为每个导出函数写明翻译后的定义、手册条目、功能目标和安全目标，并列出无文档函数和非空性目标。

**登记表（registry）。** `tests/audit/` 下三份手工维护的列表：`goals.txt`（每个目标）、`theorems.txt`（构成结论的定理）和 `proved-goals.txt`（已有类型完全相同的登记定理的目标）。

**几个数字。** 目标构建有 86 个有文档的函数。必需目标有 63 个：52 个单函数安全目标、4 个序列安全目标、3 个拒绝目标和 4 个非空性目标；31 个 gz 函数共用一个序列目标，三个 `inflateBack` 函数共用另一个。`goals.txt` 中有 239 个目标，其中 193 个有登记的定理；这里面包括并非必需的功能目标和内部目标。状态页统计的是全部 239 个。

**仅关于模型的命题。** 关于 `ZlibF/Spec/Functional/` 中抽象 API 模型的定理，而不是关于翻译后的 C。在另有定理把两者联系起来之前，它对实现什么也没有说。

## 状态

**已检查（checked）。** 定理在集成分支 `dev` 上，并且快速关卡在该提交上全部通过：Lean 内核检查过这个证明。每个已登记的定理也都是已检查的。状态页上的“已检查”专指已检查但尚未登记的定理。

**已登记（registered）。** 定理列在 `tests/audit/theorems.txt` 中，它的目标列在 `tests/audit/proved-goals.txt` 中。此后验收审计要求该定理的类型与目标完全相同。

**已验收（accepted）。** 定理已登记，并且验收套件在某个具名提交上全部通过。只有已验收的结论才作为最终结论报告，而且总是带着那个提交。

**未完成（open）。** 还没有类型相同的登记定理的目标。

**不在计划内（not planned）。** 项目不为之投入工作的目标。它从不被称为“已证明”。

## 模型

**故障（fault）。** 模型对一次没有正常返回的运行给出的结果。C 可能到达的每一种未定义行为都产生 `Fault.ub`；循环耗尽燃料则产生 `Fault.outOfFuel`。安全定理说明没有任何运行产生这两者。有一个目标把两者分开：gz 序列目标证明在任何世界里都不会出现 `Fault.ub`，并证明六个读取调用在有读取预算时返回。

**燃料（fuel）。** 翻译后的每个循环的迭代次数上限：`2^64`（`ZlibF/Runtime/Monad.lean`）。结论为正常返回的定理证明了这个上限永远达不到；本项目所说的“终止”就是这个意思。

**堆。** `ZlibF/Runtime/` 中的运行时内存模型：每类对象一张表（字节数组、字数组、`z_stream` 记录、gzip 头部、三种状态记录），加上静态表和分配器的簿记。

**块。** 堆中的一次分配，用一个编号指称。某张表在该编号下存有对象时，这个块就是**存活**的。释放过的编号不会再用。

**指针。** `NULL`，或者“某个对象加偏移”的引用。模型里没有表示未初始化指针的值：新分配内存中的指针字段读出来是 `NULL`，所以证明要说明指针字段在被读取之前已被写入（[可信基础](trusted-base.md)第 2 项）。

**良构的堆。** 多数目标对调用开始时的堆陈述的三个条件：`Fresh`（下一个块编号及其以上没有存活的块）、`Uniq`（一个块编号至多在一张表中存有对象）和 `LibraryGlobals`（静态表就是所选构建的那些表）。它们描述的是模型的簿记；C 调用者无法破坏它们（[模型的限制](model-limits.md)）。

**`ByteObjectsFit`。** 堆中每个字节数组都小于 `2^63` 字节，即 LP64 下单个对象大小的上限 `PTRDIFF_MAX`。它不限制内存总量，也不限制流的长度。

**分配预言。** 堆的字段 `allocOk`：从“第几次分配尝试”到“成功或失败”的函数。目标对每个预言量化，所以涵盖了分配失败的每一种模式。

**任意初值函数（garbage function）。** 堆的字段 `garbage`：给出新分配内存中每个整数单元的值。目标对每个这样的函数量化，所以对未初始化整数的任何内容都成立。

**帧（frame）。** 一次调用可以写的那些块和字节范围。“只写它的帧”是说：其余每个存活的块在调用前后相同（`Frame`、`BufferFrame`）。

**账本（ledger）。** 目标结论中对分配的精确记账：调用新建了哪些块、释放了哪些块（`LiveChange`）。“不泄漏”是说：调用之后仍存活的每个块，要么调用之前就存活，要么归这个流或句柄所有。

**拥有。** 流或句柄的状态指向某个块时，这个块就归它拥有：状态记录、窗口、哈希表、待输出缓冲区（`StreamOwned`、`GzOwned`）。

**表示不变量。** 流的状态所具有的、每次调用都保持的性质，例如 deflate 流的 `DGood`、inflate 流的 `Good` 和 gz 句柄的 `GzInv`。它由 init 或 open 函数建立。

**可信基础。** 证明所依赖而内核并不检查的东西，共六项：Lean 内核与审计程序；运行时模型；手工翻译；选定的源码；构建配置与外部世界的模型；以及命题本身。见[可信基础](trusted-base.md)。

**固定版本（pin）。** 子模块 `zlib/` 所指向的上游 zlib 提交。被验证的源码是这个固定版本加上 `patches/` 中按文件名顺序应用的补丁。

## 前提

**前置条件、前提。** 定理对其输入所作的假设。

**偏离。** 比 `zlib.h` 允许的范围更窄的前置条件。它写在陈述它的那个定义的文档注释里，并列在[偏离记录](deviations.md)中。

**分离前置条件。** 调用者的各内存区域互不重叠，也不与流自己拥有的存储重叠。定理把它写成一条假设。

**`DefaultOrNull`。** 流的 `zalloc` 和 `zfree` 各自是 `Z_NULL` 或库的默认函数。使用自定义分配器的流不在任何目标之内。

**`StreamBuffers`。** 关于 `next_in`、`avail_in`、`next_out`、`avail_out` 的假设：每个范围是 NULL 或可读（输出范围还须可写），都不落在流自己的存储里，并且两个范围相互分离。安全目标中的每次 `inflate`、`deflate` 和 `deflateParams` 调用都假设它。

## gzip 文件世界

**世界。** 模型中供 gz 函数使用的操作系统状态（`ZlibF/Zlib/gzfs.lean` 中的 `Fs`）：文件、打开的描述符、`errno`，以及两个预言，一个管系统调用，一个管 `vsnprintf`。gz 安全目标对每个良构的世界成立。

**系统调用预言。** 世界中的一些字段，为每次 `open`、`read`、`write`、`lseek` 和 `close` 调用决定：按普通文件行事、以选定的 `errno` 失败，或者返回该调用的 POSIX 契约之内的某个选定结果。

**读取预算。** 一个描述符还能交付的字节数（`readBudget`）。六个 gz 读取调用的终止，是在预算小于 `2^61` 字节（`ReadsFinite`）的条件下证明的。

**叶子（leaf）。** 关于一个函数或一组调用的定理，序列定理由这些定理拼装而成。`ZlibF/Proof/gz.sequence-safety.lean` 中的 `GzReadLeaves` 把 gz 读取调用的各个叶子打包在一起。

## 检查

**差分测试。** 用同一输入分别运行真实的 C 和 Lean 翻译，再比较结果。它是忠实度的证据，不是证明。

**证明变异体。** 故意写错的翻译，例如去掉一处检查。可靠的证明在它上面必须失败。

**快速关卡。** `build` 和 `no-sorry` 两个作业。每次推送和每个拉取请求都会运行。

**验收套件。** 公理关卡、目标精确匹配、自测、证明变异体和差分测试。它每晚在 `main` 上运行，也可按需运行。

**公理关卡。** 审计的一部分：遍历登记定理所依赖的每个声明，只要出现 `propext`、`Classical.choice`、`Quot.sound` 以外的公理就拒绝。

**目标精确匹配。** 审计的一部分：要求登记定理的类型与它对应的目标完全相同。多带一条前提的定理不算数。

**内核重放。** 审计在一个全新的环境里用 Lean 内核重新检查编译好的证明，不把先前某次构建的结果当作可信。

**覆盖颜色。** [进度](progress.md)的目标图中节点的颜色：灰、蓝、黄、绿，表示某个目标的定理覆盖了多大的输入范围（[输入配置](spec/input-configurations.md)）。它不是状态层级。

**里程碑。** `inflate` 得证、`deflate` 得证、某个序列目标得证，或者新增约二十个已检查的目标。
