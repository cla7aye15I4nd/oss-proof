# 外部 I/O：文件、格式化与局部存储

gz 函数调用操作系统和 C 库：`open`、`read`、`write`、`lseek`、`close`、`fcntl`、`strerror`、`snprintf` 和 `vsnprintf`。本页说明这些调用的模型 [`ZlibF/Zlib/gzfs.lean`](../../ZlibF/Zlib/gzfs.lean)。这个模型是被信任的：内核对照它检查证明，但不对照 Linux 检查它本身（[可信基础](../trusted-base.md)）。

要点是：每个系统调用都可以返回其 POSIX 契约允许的任何结果，由一个预言选择；gz 接口的安全性是对每一个预言证明的（`Goal.gz_sequence_safety`；[gzip 文件](../proof/gzip.md)）。这个结果的前提见[偏离记录](../deviations.md#gzip-file-interface)。

## 堆之外的世界

文件系统、描述符表和 `errno` 合成一个记录 `Fs`，与堆分开。一个 gz 计算的类型是 `G α = StateT Fs C.M α`：它接受一个世界和一个堆，返回一个值以及新的世界和新的堆，或者返回一个故障。

- 路径是扁平的字节串。节点保存一个文件的字节，或者是一个目录标记。
- 已打开的描述符保存它的节点、一个位置，以及读、写和追加标志。
- 描述符是 C 的 `int`。
- `Fs` 还保存下文说明的预言。

`FileSystem fs` 是世界的良构条件：描述符和名字指向存在的节点，位置和文件大小至多为 `2^63 - 1`，目录不会以写方式打开。它只约束文件部分；预言的每个取值都是允许的。

## 操作系统预言

`read`、`write`、`lseek`、`close` 和 `open` 的每次调用都取下一个调用编号，并询问预言该怎么做。预言要么让这次调用按普通文件的方式进行，要么选择另一种结果。预言的每个取值都被映射到该调用的契约之内（截断或钳制，从不拒绝），所以每个世界都是合法的。

| 调用 | 普通文件行为（预言的默认值） | 预言可以选择的其他结果 |
| --- | --- | --- |
| `open` | 读模式或写模式；创建、排他、截断和追加都有表示。无效的模式或模型中的路径失败会设置 `errno` 并返回 `-1`。新描述符是从 3 起最小的空闲编号。当 `2^31` 以下没有空闲编号时：在创建或截断任何东西之前，以 `EMFILE` 返回 `-1`。 | 在创建任何东西之前，以任意非零 `errno` 返回 `-1`。或者成功，并把新描述符移到 `2^31` 以下的任一空闲编号。 |
| `read` | 复制所请求的文件字节，至多到文件末尾，并截断到读取预算。无效的描述符、错误的访问模式和目录都会失败。 | 以任意非零 `errno` 返回 `-1`。或者，对请求 `n` 个字节的读取，交付任意数据，字节数是 `[0, n]` 内的任意 `k`，并截断到读取预算，不论描述符处于什么状态。 |
| `write` | 在当前位置写入，追加模式下在末尾写入。定位到末尾之后再写入，会用零填充空隙。越过 `fsizeLimit` 的写入是短写；在该限制处的写入以 `EFBIG` 失败。 | 以任意非零 `errno` 返回 `-1`。或者对非空缓冲区返回 `[1, n]` 内的任意计数（对空缓冲区返回 0），不改变文件。 |
| `lseek` | 支持相对起点、当前位置和末尾的偏移；负的结果或大于 `2^63 - 1` 的结果被拒绝。 | 以任意非零 `errno` 返回 `-1`。或者返回 `[0, 2^63 - 1]` 内的任意值，不移动描述符。 |
| `close` | 释放描述符；无效的描述符会失败。 | 以任意非零 `errno` 返回 `-1`；描述符仍被释放。 |
| `fcntl` | 没有效果。 | 无。 |
| 成功之后的 `errno` | 不变。 | 成功的调用可以留下任意 `errno`。库自己对 `errno` 的重置是另外的效果。 |
| 读取预算 | 没有上限。 | 对每个非负的描述符编号，给出它还可以交付的字节数；每次 `read` 都被截断到这个数，并从中扣除。负的描述符没有预算。 |

预言有意比任何真实系统都宽。它逐次调用地覆盖管道、套接字、设备、信号（`EINTR`）、非阻塞描述符（`EAGAIN`）、瞬时失败和并发文件修改所产生的结果，而不表示这些对象本身。普通文件部分不表示权限、目录遍历、链接，也不表示通过复制描述符形成的共享；`O_NONBLOCK`、`O_CLOEXEC` 和 `O_LARGEFILE` 没有普通文件效果。

有两种结果被模型排除。它们是关于 Linux 的被信任的事实，不是某个定理的前提：对非空缓冲区的 `write` 从不返回 0；`close` 失败时也释放描述符。

预言就是 `Fs` 的字段 `nos`、`readChoice`、`writeChoice`、`lseekChoice`、`closeFail`、`openFail`、`openFd`、`okErrno` 和 `readBudget`。它们的默认值给出普通文件行为，只供可执行的测试驱动程序使用；每个目标都对所有世界量化。`gzfs.lean` 的注释给预言的各个子句编了号：M1 是 `read`，M2 是 `write`，M3 是 `lseek`，M4 是 `close`，M5 是 `open`，M7 是读取预算。没有 M6。[偏离记录](../deviations.md#gzip-file-interface)中“gz 读取终止”一行使用了 M7 这个标签。

## 错误文本

`errno` 是世界中的一个整数。`strerror` 返回一个指向静态文本的指针；模型有一张固定的 Linux 文本表，对其他每个 `int` 值有一条后备文本。

模型只允许读取最近一次 `strerror` 返回的指针：每次调用都使先前的指针不可读，即使 `errno` 相同。这表示的是顺序失效。线程退出、并发调用和语言环境变化没有表示。这个指针是只读视图；它不是一次分配，不改变存活块的集合，也不改变分配预言。

翻译在四处调用 `strerror`（`gzread.c` 两处，`gzwrite.c` 两处）。每一处都立即把指针交给 `gz_error`；后者把文本复制到自己的消息分配中，既不保存也不释放这个指针。

C 字符串字面量是另一回事：它们是库源码中各字面量组成的一张封闭的只读表，每个字面量有一个固定指针。

## 外部调用的缓冲区

`storeBytes` 存放 `read` 或格式化函数产生的字节。它经由一个临时块复制，然后释放该块，所以它的效果是一次块复制，不是一串字节存储。内存操作和其他地方一样检查对象边界、只读的目的缓冲区和重叠。无效的用户缓冲区是模型故障；模型不重现操作系统的 `EFAULT`。

## 格式化输出

可变参数是一个由 `VaArg` 值组成的列表：有符号和无符号的 32 位、64 位整数，以及字符串指针。`gzprintf` 接收这个列表，并委托给 `gzvprintf`。C 的 `va_list` 的 ABI 存储没有表示。

格式化函数支持转换 `%%`、`%c`、`%s`、`%d`、`%i`、`%u`、`%x`、`%X` 和 `%o`，标志 `-`、`0`、`+`、空格和 `#`，十进制的宽度和精度，以及长度修饰符 `l`、`ll`、`z`、`j` 和 `t`。无符号转换也接受同宽度的有符号参数种类，并重新解释它的位。

不支持的有：浮点、`%p`、`%n`、用 `*` 给出的宽度或精度、修饰符 `h` 和 `hh`，以及 `%ls`。不支持的转换，或者缺失的、种类不对的参数，是模型故障。没有返回任意字节的后备行为。因此安全目标要求格式是有表示的格式（`Formatted`）；[偏离记录](../deviations.md#gzip-file-interface)中有对应的一行。

和 C 一样，模型有两个函数：

- `snprintf` 用于 `gz_error`、`gz_open` 和 `gzdopen` 的固定格式。它是确定的。它至多写入 `capacity - 1` 个文本字节和一个 NUL，返回未截断的长度；该长度超过 `INT_MAX` 时返回 `-1`。
- `vsnprintf` 用于 `gzvprintf` 中调用者给出的格式。它的行为相同，只是任何一次调用都可能失败，由第二个预言（`printfOk`）选择。失败的调用返回 `-1`，设置非零的 `errno`，并在缓冲区内留下任意字节和一个 NUL。glibc 方面的依据见[可信基础](../trusted-base.md)。

调用之后，`gzvprintf` 仍然执行自己的长度检查、哨兵检查、缓冲区腾空和错误处理。格式化模型不替代这些语句。

## gz 翻译中的指针与局部存储

- `gzFile` 是指向句柄记录的公开前缀 `x` 的指针（`GzFilePtr`）。`castState` 恢复出这个记录，`strmOf` 指出内嵌的 `z_stream`。一次字段写入加载并存回这同一个记录，所以句柄、它的公开前缀和它的内嵌流始终是一个对象。
- 调用者的标量单元是小端字节块：`gzerror` 的可选参数 `int *errnum`（四字节），以及 `uncompress2` 的长度单元（八字节）。
- `gz_load` 内部的 `unsigned *have` 是一个返回值（[规范化 1](translation.md#the-accepted-normalisations)）。每个调用者在成功和失败时都存储它。有一点**尚未由证明确认**，要靠审查：在每个调用点，这次存储发生在效果顺序中与 C 相同的位置。
- 被取地址的局部变量是一个新分配的对象，它不消耗分配失败预言，并在每条返回路径上被释放：`gzgetc` 和 `gzputc` 的单字节缓冲区，以及 `uncompress2_z` 的局部流和长度单元。
- `z_off64_t` 上的文件位置运算使用带检查的 64 位操作。

模型允许 `NULL + 0`。这并不使悬空指针上的运算变得可以接受。

## 源码是打过补丁的源码

有四个补丁修改 gz 文件（[补丁登记表](../../patches/README.md)）：

| 补丁 | 改动 |
| --- | --- |
| 0002 | `gzseek64` 的范围检查 |
| 0003 | 透明模式下，在 `gz_load` 之前设置 `x.next` |
| 0004 | 位置 `x.pos` 保持在 `z_off64_t` 之内 |
| 0005 | `x.next` 只按非零的量前进 |

`gz_reset` 仍然不初始化 `x.next`，直接读取之后 `x.next` 仍然指向调用者的缓冲区；补丁 0005 去掉了在这些值上的运算。各补丁背后的报告见 [gzip 文件](../proof/gzip.md#source-reports-and-patches)。

## 差分证据

gz 的差分用例由 [`tests/gen/gz.py`](../../tests/gen/gz.py)、[`tests/c/gz.c`](../../tests/c/gz.c) 和 [`tests/lean/Driver/Gz.lean`](../../tests/lean/Driver/Gz.lean) 定义。它们把每个操作在临时的真实文件上返回的结果，与在 `Fs` 上的运行相比较。同一组用例还比较 `uncompress2` 的字节和长度。

驱动程序从默认预言出发，也就是普通文件行为。一个测试用例可以让选定的一次 `read` 调用失败，也可以让一次使用调用者格式的 `vsnprintf` 调用失败。预言的其他每一种选择都只由证明覆盖。

结果一致，是把翻译和世界模型合在一起，对照选定的 C 执行做的测试。它是忠实性的证据。它不是编解码器正确性的证明，也不是所有错误路径、所有 POSIX 行为或无泄漏的证明。这些测试何时运行，见[检查](../checking/README.md)。
