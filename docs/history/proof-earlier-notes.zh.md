# 早期证明笔记

本页保存 2026 年 11 月从 [`docs/proof/`](../proof/README.md) 各页移出的段落；当时每个必需的安全目标都已有登记的定理。这些段落写于证明尚未完成的时候，描述的是计划、更早的开发和未确认的实验。它们不是当前事实，这里也没有任何内容是本仓库的结果。每个组件当前的论证在它自己的证明页上。

每个标题下的正文未作改动，只把链接调整为相对于本目录。

## `gzsetparams` 实验

来自 gzip 页。该实验没有在本仓库中复现。它是一份未确认的报告；[进度](../progress.md)把它列在待复查的报告中。

另有一个历史实验报告：输出缓冲区接近满时，`gzsetparams` 返回成功，却没有应用级别 0。实验先以级别 6 写入可变的伪随机前缀，再请求级别 0，然后写入 200,000 个零字节。部分生成文件仍远小于存储方式的第二段。提出的机制是 `deflateParams` 返回的 `Z_BUF_ERROR` 被忽略；数据仍然有效，影响的只是压缩参数。源代码确实忽略该返回值，但这个实验没有在本工作区独立复现。它仍是未确认的报告，不是新的发现，也不构成打补丁的理由。

## Gzip：早先的 I/O 方案

来自 gzip 页的“审查边界”一节。第二段已经过时：模型现在有了它称为方案的操作系统调用预言机。

C 的内存义务包括：句柄存活，路径、模式和格式字符串以 NUL 结尾，调用者范围可读或可写，`memcpy` 的范围不重叠，可变参数类型有效。运行时允许同一次字节分配中不相交的切片；更早关于必须是不同块的说法已经过时。被取址的局部字节有临时分配，并在每次返回时释放。标量输出参数和内嵌记录引用采用[外部 I/O 模型](../design/external-io.md)所述的选择；这些选择需要各自的别名和帧论证。

较早的方案对任意短读写和失败量化，带有显式的操作系统预言机和公平性前提。当前模型实现的是一个较小的普通文件世界。无论是阅读源代码，还是把该模型与选定的执行相比较，都不能证明更宽的断言。模型限制属于公开定义域审查的一部分，不是调用者隐含的承诺。

## 重叠缓冲区界限：早先的路线

来自树页。这个界限现在已对每个 `memLevel` 证明，路线见[树页](../proof/trees.md)。

早期工作研究真实 Huffman 路径上的 Fibonacci 增长。一个深的低频叶子会迫使周围子树具有足够的总权重；形式化的深度／频率定理便可限制前缀输出成本。早先 `theorems_trees_fib.txt` 记录的 `build_tree_fib_stmt_holds` 是历史上的构造器结果。在那个早期开发中，`dynFits_dynOf_of_fib` 覆盖 `memLevel` 4 和 5，`dynFits_of_push` 覆盖 6 到 9。复用时必须为当前翻译推导其准确的频率、同频排序、深度及成本前提。它们并不建立当前整个压缩器的定理。

对于 `memLevel` 1、2、3，B 只有 128、256、512。固定码的余量约为 16 到 64 字节，动态描述可能消耗相近的空间。历史搜索没有发现真实块违规，记录到的最接近情形还剩 47 字节。搜索是证据，不是证明。历史上的 `lowmem_lp_bound` 路线使用线性规划对偶证书；已检查的证书本身并没有完成从真实块频率和前缀到所需界限的连接。

限制为 `memLevel ≥ 4` 的定理必须明确写出该前提，并列入[偏差记录](../deviations.md)。它不能支持对 `zlib.h` 允许的全部配置的安全性断言。全部重叠情形的权威当前记录在[进度](../progress.md)。

早期的重叠分析包括对内存级别 4 到 9 的已检查分类论证，以及对级别 1 到 3 的松弛分析。这些不同形式的证据并没有证明全部实际执行。数学论证见[树证明指南](../proof/trees.md)。

## 回调解码器：迁移来的定义域表

来自回调页。已证明定理的定义域见[回调页](../proof/callbacks.md)。

回调假设描述的是调用者提供的代码。它们与禁止使用的、关于库内被调用函数的假设是两回事。调用 `inflate_fast` 或 `inflate_table` 的定理，仍然需要一条关于翻译后的该函数的定理。

| 迁移论证中的条件 | 相对于 API 的边界 |
| --- | --- |
| 默认分配器，或由初始化替换的空分配器字段 | 自定义分配器实现在本模型范围之外 |
| 窗口由一个字节块表示，从其偏移起有 `2^windowBits` 字节的空间 | 调用者必须提供有效的可写范围 |
| 回调不分配也不释放堆块 | 比文档对返回输入的生命周期要求更强 |
| 只有输入回调写它的输入块 | 一种方便的所有权约定，并非对每个合法回调的完整刻画 |
| 回调不变量 `R` 只依赖它自己拥有的块 | 把回调的效果与解码器状态隔开 |
| `InFinite` 限定仍可交付的输入 | 终止所需；API 并不保证回调最终会结束 |

度量 `phi` 把已持有的位数、剩余字节数和仍可交付的输入组合在一起。一个无限产出的回调可以让 `inflateBack` 永不返回，而不引起 C 的未定义行为。有限输入的定理必须写出这个前提，而不能对公开接口允许的每个回调断言无条件终止。所有较窄的定理定义域都必须明确写出，并记录在[偏差记录](../deviations.md)中。

表的返回分类并不建立有界的规范链接。输出与历史分属不同数组的快速路径定理，不覆盖输出位于回调窗口内的情形。实际调用者必须在返回的堆上建立已安装表和复制的前提。历史上关于缺失 whave 的报告仍然尚未完成确认；普通 inflate 的例子不能解决这个 API 的问题。

## 流解码：`inflateCopy` 的指针比较

来自 inflate 页。这个比较现在已由补丁 0001 替换，复现在 `docs/findings/inflate-copy-fixed/` 下。

在指针模型下，对动态表与静态表指针做关系比较，需要审阅源代码。历史上提及的 `inflateCopy` `ub.patch` 不构成补丁授权：选定的补丁集只由 `patches/README.md` 定义。

现有源代码用 `>=` 和 `<=` 检查 `lencode` 是否位于 `codes` 内。使用固定表时，它们是不同对象。翻译保留这些比较及其故障，不实现历史建议 `lencode == codes`。早期笔记记录了在固定块中暂停后复制流所触发的运行时检测器指针对报告，以及采用建议修改后的无报告运行。这是历史证据，不是本次文档修订执行的复现，也不是已应用的补丁。

## 工具函数、Adler-32 与 CRC-32：早先的模型

来自工具函数、Adler-32 和 CRC-32 各页。

常量返回仍是准确契约：错误的版本指针或改变的标志位必须使该函数的证明变异失败。早期文档曾把这些包装函数归为旧模型中的已完成项。当前结果需要[检查指南](../checking/README.md)规定的准确目标、登记、变异证据和已审查的 CI。当前检查点见[进度](../progress.md)。

早期工作为字节算法提供过 Lean 论证。复用时必须对照当前模块检查陈述、机器位宽、所选补丁、执行关系和前置条件。[方法](../proof/method.md)解释非空泛性与变异检查的要求。

早期工作使用逐项的长证明，并给出名为 `crc32_z_correct` 和 `multmodp_eq_gf2` 的结果。这些是代数方面的历史参考，不是当前翻译后运行的验收证据。
